# 실제 서버 연결 안내

2026-10-02: Next API와 Supabase 마이그레이션 구현 완료. 현재 기본 모드는 `local`이고 Sites는 정적 편집 미리보기입니다. **실제 Supabase 프로젝트, SQL 적용, OAuth 공급자 설정, 원격 서버 배포는 아직 연결되지 않았습니다.**

## 연결 순서

1. 소유자가 선택하고 비용을 확인한 봄결 전용 Supabase 프로젝트를 사용합니다. 다른 앱의 DB에는 이 마이그레이션을 적용하지 않습니다.
2. `supabase/migrations/20261002084131_invitation_backend.sql`을 적용합니다. `tests/rls.sql`은 전용 개발 프로젝트에서 트랜잭션 후 되돌리는 정책 검증입니다. 운영 데이터와 섞지 마세요.
3. `.env.example`을 기준으로 서버 환경을 설정합니다. `NEXT_PUBLIC_DATA_MODE=remote`, `NEXT_PUBLIC_SITE_URL=https://실제주소`, `BACKEND_ENABLED=true`, Supabase URL·publishable key·server secret·별도 32자 이상 `ABUSE_HASH_SECRET`이 필요합니다. 서비스 키와 해시 키는 서버에만 보관합니다.
4. Supabase Auth에서 카카오·구글 공급자를 설정하고 공급자 콜백은 Supabase가 안내하는 주소를 사용합니다. Supabase Site URL은 실제 앱 주소, 허용 Redirect URL은 `https://실제주소/api/auth/callback*`으로 제한합니다. 앱이 생성하는 `flow` 쿼리를 허용해야 합니다. 네이버 로그인은 아직 연결되지 않았습니다.
5. Next 서버를 다시 빌드·배포하고 실제 두 계정으로 초안·공유·업로드·방명록·RSVP를 확인합니다. 카카오 공유·지도 키는 각 개발자 콘솔의 실제 도메인 등록 후 설정합니다.

사이트 주소나 `NEXT_PUBLIC_*` 값을 바꾸면 다시 빌드해야 합니다. `ALLOW_LOCAL_SUPABASE=true`는 로컬 HTTP 테스트 전용입니다. 배포 경계가 직접 덮어쓰는 것이 검증된 경우에만 `TRUSTED_PROXY_HEADER`를 설정합니다. 비워 두면 하객들이 보수적인 공통 한도를 사용합니다.

## 구현과 보호 장치

새 운영 의존성을 설치하지 않고 기존 Next/Node와 Supabase HTTP API를 사용했습니다. 비밀번호는 Node의 salted scrypt와 일정 시간 비교로 확인합니다. 기존 명세의 bcrypt 패키지는 추가하지 않았습니다. 로그인 쿠키는 HttpOnly·SameSite=Lax이고 운영에서는 Secure입니다. 사용자는 공급자의 Supabase `/user` 검증 후에만 소유자로 인정합니다. 브라우저에는 서비스 키나 세션 토큰을 저장하지 않습니다.

DB RLS는 소유자·공개되고 만료되지 않은 청첩장만 읽게 합니다. 클라이언트의 직접 쓰기 권한은 철회해 API 검증을 우회할 수 없게 했습니다. 참석 응답은 소유자만 읽으며, 방명록의 비밀번호 해시는 응답에 포함하지 않습니다. 비공개 Storage의 사진은 소유자나 게시된 청첩장에 첨부된 경우에만 60초 서명 URL로 열립니다. 공유를 중지해도 이미 발급된 서명 URL은 최대 60초 유효할 수 있습니다.

서버는 같은 사이트 Origin, JSON 64KiB, 요청 읽기 5초, 외부 HTTP 8초, 작업별 요청 20회/분·200회/일, 사용자 100회/일, 전역 100회/분·2,000회/일 한도를 검사합니다. 한도 DB가 응답하지 않으면 쓰기를 차단합니다. 저장은 작업·사용자·요청 키에 묶어 하루 동안 중복을 방지합니다. 실패한 쓰기 요청은 같은 키로 즉시 재시도할 수 없습니다. 클라이언트는 자동 재시도를 하지 않습니다.

사진은 로그인 후 JPG/PNG/WebP만 검사합니다. 서버 입력 2MiB·1,200만 화소, 출력 WebP 1MiB·1,200px, EXIF 제거, 동시 변환 2개, 같은 사진 중복 제거를 적용했습니다. 업로드 전역 50MiB/일, 사용자 누적 100MiB, 전역 누적 500MiB를 보수적으로 예약합니다. 실패하거나 삭제한 용량은 자동 환급하지 않습니다. 청첩장은 사용자당 5개, 방명록과 참석 응답은 각각 초대장당 1,000개로 제한합니다. `BACKEND_ENABLED=false`는 서버 중지 스위치입니다.

## 확인된 증거와 연결 후 필수 확인

- Next 서버를 실제 실행한 HTTP fixture 통합 테스트: 소유권·공개/비공개·사진·위조 파일·비밀번호·중복·CSRF·한도 실패 경로.
- TypeScript, lint, Next production build, 한 파일 미리보기 build, 의존성 취약점 검사.
- 모바일 19종 표지 이미지 로딩·화면 넘침, 실제 사진 선택·편집·저장 화면.

실제 SQL 문법·DB RLS 테스트는 **미실행**입니다. Docker 실행 환경이 없고 새 프로젝트 선택도 아직 없으므로 실제 DB에 적용하지 않았습니다. 정책 검증, 공급자 로그인, 두 계정 접근 분리, 실제 저장·공유, Supabase 비용·용량 관측을 확인하기 전에는 운영 백엔드 완료로 표시하지 않습니다. 결제·요금제·엑셀 내보내기는 별도 구현 범위입니다.
