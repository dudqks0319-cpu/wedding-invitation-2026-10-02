사용자 요청으로 현재 소스 `147f0cef3a6462e1e903a3335967fa19f71cf7e5`를 실행 점검했다. 앱 소스 수정·운영 DB 연결·재배포는 하지 않았다. 결과는 **로컬 검증 일부 통과, 운영 연결과 오류 수정 필요**다.

- 같은 Sites 산출물을 사용자 Mac의 `http://127.0.0.1:4174/`에서 실행했다. 이 주소는 사용자 Mac에서 열 수 있으며 Claude의 별도 실행 환경에서는 열 수 없다.
- 실제 로컬 화면: [디자인](evidence/local-design-20261003.jpg), [편집·저장](evidence/local-editor-saved-20261003.jpg), [새 작성에 기존 초안 복원](evidence/local-draft-collision-20261003.jpg).

설치돼 있던 Docker와 캐시된 공식 PostgreSQL/PostgREST 이미지를 사용했다. 새 이미지 다운로드·패키지 설치 없이 작업 전용 내부 네트워크와 임시 DB에서 실행했다. DB/API 외부 포트와 호스트 데이터 볼륨은 사용하지 않았다. 테스트 JWT·비밀번호·개인 데이터는 결과 파일에 저장하지 않았다.

실제 REST에서 비공개 청첩장 숨김, 소유자 초안 읽기, 다른 계정 RSVP 차단, 소유자 RSVP 읽기, 익명 RSVP·비밀번호 해시·한도 RPC 차단을 확인했다. 표지·갤러리의 JSON OR 필터는 HTTP 200이며 각각 1개, 미참조 사진은 0개를 반환했다. 사진 바이트 저장·서명 URL·카카오 캐시까지 검증한 것은 아니다.

## 재현한 문제

1. **P1 · 공개 사진 요청 한도 공유**: 신뢰할 프록시 헤더가 없는 두 개 이상 하객 요청은 같은 한도 키를 사용한다. 사진 요청 20회는 302, 21번째는 429였다. 위조된 전달 헤더를 무시하는 보호 동작도 확인했다. 하객별 분리·공개 읽기 캐시·실제 부하 검증이 필요하다.
2. **P1 · 한도 서버 장애의 페이지 오류**: 한도 RPC 장애를 주입하자 `/i/[slug]` 서버 페이지가 HTTP 500과 오류를 반환했다. API의 오류 변환과 달리 페이지에서 예외가 처리되지 않는다. 응답 스트리밍 시 최종 HTTP 상태는 달라질 수 있으나 사용자 오류 화면은 관측됐다.
3. **P2 · 새 작성의 기존 초안 덮어쓰기**: 기존 청첩장 편집에서 이름을 바꾸고 저장 없이 나간 뒤 같은 디자인의 새 작성으로 들어가면, 기존 slug와 미저장 이름이 복원된다. 저장하니 기존 항목을 덮어썼다. 브라우저 저장 모드에서 합성 데이터로 재현했다.
4. **P2 · 공개 DB 목록 수집 허용**: 실제 PostgREST의 익명 `GET /invitations?select=id`가 공개 항목 목록을 HTTP 200으로 반환했다. 현재 SQL 정책에 따른 결과이며, 테스트 기대 응답 일치가 최소 권한 충족을 뜻하지 않는다. 비공개 항목과 RSVP는 차단됐다.
5. **P3 · 입력·오류 안내 불일치**: 없는 주소의 비로그인 요청은 401 로그인 안내를 반환했다. 외부 배경음악 주소 저장은 400으로 거부했다. 큰 JSON은 413으로 정상 차단됐다.

누적 저장량 회복·사진 삭제, 전역 SQL 잠금 병목, 게시 전 AI 예시 사진 안내는 코드 검토상의 잔여 사항이다. 실제 동시 부하·장기 보관·카카오 크롤러는 수행하지 않았다.

## 보안 관점의 점검

소유권·비공개·타계정·CSRF·입력·사진 형식·비밀번호 해시·중복 요청의 부정 경로는 기존28개 실행과 실제 SQL/REST 결과로 확인했다. 공개 DB 직접 읽기와 공개 조회 한도 문제는 잔여 위험으로 기록했다. 의존성 변경은 없으며 기존 npm audit 결과 이후 새 설치도 없다. 이번 공개 문서·JSON·텍스트 로그10개에서 개인 대화 URL·사용자 절대 경로·키/토큰 패턴을 확인했고 일치값은 없었다. 개인 앱 캡처와 원시 작업 자료는 Git에서 제외한다. 실제 운영 개인정보·공급자 인증·비용 및 부하 보호의 최종 검증은 운영 연결 뒤 필요하다.
